## 新增

### 切换主题的转场动画

之前切主题是直接重建 Activity，整个界面「啪」地闪一下。现在分两种：

| 操作 | 动效 |
|---|---|
| **深色模式** | **圆形扩散**，方向每次交替：一次从中心向外推开，一次从四周向中心合拢 |
| **配色** | **墨水扩散**：软边 + 一圈新主题的中心色，颜色像墨滴一样化开 |

实现上没有用 `createCircularReveal`（它只能硬裁，做不了「只保留圆外」的反向），
而是用一个 `Path` 配 `INVERSE_EVEN_ODD` 填充，同一个 View 支持两个方向。
墨水效果用径向渐变做羽化遮罩。

## 修复

### 曲库列表滑动「只能一点一点划」（重要）

只有曲库的歌曲列表是**自绘 + 自己实现的惯性**，其他页面用的是系统 `ScrollView` ——
所以问题只出在曲库。一共三个叠加的 bug：

**① 惯性方向是反的**

```java
velocity = -vt.getYVelocity();   // 上滑后惯性往回推
```

上滑之后惯性把列表**推回来**，净效果就是只前进一点点。
**这个 bug 从一开始就在**，之前误判成「缺少回弹」，白绕了一圈。

**② 帧循环只有 30fps**

`postOnAnimationDelayed(loop, 16)` 是「下一帧**再等** 16ms」，实际间隔约 32ms。

**③ 摩擦太狠** —— 4000px/s 的滑动只滑 1022px。

最后索性**换成系统的 `OverScroller`**，跟 `ScrollView` 用同一套物理，
从此曲库和其他页面的滑动手感一致。

> 换的时候差点又踩一个符号坑：`OverScroller` 的 `velocityY` 正值表示朝 Y 增大方向，
> 而本 View 的 `scrollY` 增大表示手指上滑（`getYVelocity()` 为负），
> 两者约定相反，必须传 `-velocity`。

### 掉帧

| 问题 | 原因 |
|---|---|
| `saveLayerAlpha` 每行每帧调用 | 每个可见行分配一块离屏缓冲；且入场动画结束后 `alpha=255` 的图层毫无作用却照样分配 |
| 每帧 `new LinearGradient` | 持续制造垃圾 |
| `subtitle()` / `durationText()` 每帧新建字符串 | 8 行 × 60 帧 × 2 ≈ 每秒 1000 次分配 |
| `blendLab` 每帧计算 | 走 Lab 色彩空间往返（含 cbrt） |
| 帧循环 120Hz 空转 | 列表静止时也在占用 UI 线程，改为**按需启停** |
| `setLayerType(HARDWARE)` | 内容每帧都在变，缓存层反而多一次离屏合成 |

实测：99 分位帧时间 **8ms**（预算 16.7ms）。

### 其他

- **滚动阻尼累加错误** —— 每帧把「已阻尼的值」当基数再加原始位移，阻尼等于被反复重置
- **内容不足一屏时不该能拖** —— 之前空列表一拖就回弹
- **切主题时有一段全黑** —— `DST_OUT` 是擦除类混合模式，必须在自己独立的图层里
- **`chip()` 里的 NPE** —— `if (action != null) lastTapped = box; action.run();`
