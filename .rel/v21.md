## 新增

### 导入整个文件夹 📁

之前只能一个个挑文件 —— 音乐都放在一个目录里的人，得点几十次。

现在「曲库」页多了一个 **「导入文件夹」** 按钮：选一个目录，
递归把里面（**含所有子目录**）的音频全部导入。

- **递归扫描**，子目录也会翻
- 用**广度优先**而不是递归函数 —— 目录层级深的时候递归容易爆栈
- 导入完会告诉你：扫了几个目录、用了多久、新增几首、跳过几首
- 有数量上限（5000 首 / 800 个目录），防止误选根目录把整个存储扫一遍

> **实现说明**：没有用 `androidx.documentfile.DocumentFile` —— 那是最省事的做法，
> 但它是 AndroidX 库，本项目零第三方依赖。
> 直接用系统的 `DocumentsContract` 查询，功能完全一样。

### 文件夹导入的容错

判断音频不能只看 MIME —— 很多第三方 provider 对 flac、ape 这类
会返回 `application/octet-stream` 甚至 `null`。所以：

- MIME 是 `audio/*` → 收
- MIME 是 `video/mp4` 但扩展名是 `.m4a` → 收（容器相同，有些 provider 认错）
- MIME 不认识 → 按扩展名兜底（mp3/flac/m4a/aac/wav/ogg/opus/wma/ape/mka/dsf…）
- 单个子目录读不了（权限/损坏）就跳过，**不影响其他目录**

## 修复

### 全新安装会跳过欢迎页（重要）

条款页点「同意并继续」后，本该接着看到欢迎/激活页，结果一路直接进主界面。

```java
// WelcomeActivity.onActivityResult —— 修复前
if (res == RESULT_OK) goMain();   // ← 直接进主界面，把欢迎页跳过了
```

`TermsActivity` 的注释写着「继续走欢迎页的流程」，但 `goMain()` 并没继续，是直接跳过。
改为 `proceed()` 后恢复正常：

```
条款页 → 欢迎页/激活页 → 主界面
```

> 只影响**全新安装**。已激活的用户不会遇到。
